# 建岗规范 — bot positions

一句话：岗位 = 常设项目 Bot 的岗位说明书。description 决定自动委派命中率，正文决定干活质量与记忆落点。
岗位库：`~/.mu/agent/agents/`（subagent 委派与桌面版岗位名册共用这一个库）。

## 何时建岗（判定门）

- ✅ 建：跨会话会反复派活的项目（有 HANDOFF、活跃开发、常跑任务）
- ❌ 不建：一次性任务（用通用执行岗兜底）、已判死项目、纯外部依赖目录（只在相关岗正文里写关联警示）
- 拿不准 → 不建，等第二次同类任务出现再建；归属不清的任务先交主会话判断，不靠新建岗位消化

## 岗位文件规范（`~/.mu/agent/agents/<name>.md`）

### frontmatter（必填两项）

```yaml
---
name: kebab-case-english-name   # 与文件名一致
description: 一句话职责+全部委派关键词
---
```

description 是**自动委派的唯一依据**（主 agent 拿任务来这里匹配），必须含：项目名、项目根目录名、用户会说的大白话关键词（中文）、特色端口/组件名。宁多勿漏，反向同义也写（如「抠图/抠像/分割」）。

### 正文必含六节（顺序固定）

通用执行岗（叶子岗，不再向外派活的那种）只需前五节。

1. **身份行**：「你是 XX 岗位的常设负责 Bot（岗位即项目，跨任务常设，持续积累本岗记忆）」
2. **项目事实（开工必读）**：项目根绝对路径 / 唯一真相源（HANDOFF.md 路径，没有则写「首次收尾创建」）/ 关键资产与入口 / 端口 / 🚫禁令
3. **工作规矩**：该项目特有的操作纪律（3-6 条，从该项目 HANDOFF/AGENTS 提炼）
4. **收尾记忆铁律 + 规范分流**（逐字保留，这是机制钩子）：
   - 「收尾时（记忆分工铁律）：把本次进展压缩追加到 <项目 HANDOFF 绝对路径>——只留可执行事实；这是本岗位长期记忆，不写=白干」
   - 「规范分流：任务中产生的可复用规范/坑，不要只留在对话里——项目内规矩写本岗 HANDOFF 的「规矩/教训」行；跨项目通用且值得沉淀的，在回报末尾单独列一行 `LESSON: <一句话+触发条件>`，交主会话或上级 agent 裁决；勿自行改全局 skill 或路由配置」
5. **回报格式**：「产出文件路径 + 一行验证证据（命令/检查结果）」
6. **多步任务拆分与跨岗分工**（项目岗必含，整节套用）：
   1. **拆清单**：列子任务清单，逐条标注「本岗」或「跨岗」（判据：该岗域关键词，与 description 同源）
   2. **本岗自己干**：本岗域子任务按上文工作规矩执行
   3. **跨岗派发**：跨岗子任务派给对应岗位，互不依赖的并行派；不知派谁 → `ls ~/.mu/agent/agents/` 对照各岗 description，仍无匹配 → 不强派，归入回报「待派事项」
   4. **cwd 必传**：派发时把该岗的项目根（从其岗位 md「项目事实」行取）作为 cwd 传入，防其读到错误项目的 AGENTS.md
   5. **嵌套一层封顶**：不许让被派岗位再往下派岗；回报仍有跨岗残余，由你汇总后另行派发
   6. **汇总回报**：总回报按「子任务 | 负责岗 | 产出/证据」逐行列，本岗直做与外派均须出现

   桌面版岗位会话内，跨岗协作按其内建组队规则执行，本节模板不适用。

### 禁项与可选字段

- 不写 `model:`（跟会话默认，防环境漂移）
- 不写 `tools:`（除非明确要收窄权限，如纯侦察岗）
- 额外可选字段（如桌面版审批档 `approval`）以该机制自身文档为准，不确知的字段不要写
- 正文不复制 HANDOFF 内容，只**指向**（真相源单点，防双源漂移）
- 纯文档（无合法 frontmatter）不会被加载，README.md 可安全放同目录

## 建岗流程（五步，建完即验）

1. **侦察**：ls 项目根 + 读 HANDOFF/AGENTS 头部（≤30 行/文件）；无 HANDOFF → 正文写「首次收尾创建」
2. **写文件**：按上述规范写 `<name>.md`
3. **查重**：`ls ~/.mu/agent/agents/` 对照 name 与 description 关键词，同义岗合并不新建
4. **冒烟**：`mu -p "只列清单不干活：ls ~/.mu/agent/agents/ 列出岗位库全部岗位，每行=岗位名:一句话职责"` —— 新岗必须出现且职责复述准确
5. **登记**：有跨岗位登记处（名册/总 HANDOFF）就追加一行岗名，没有则省略

## 验收标准

- 冒烟清单出现新岗、职责准确
- 发一条**不点名**的真实任务，主会话命中该岗（命中旧岗说明 description 要补词）
- 项目根迁移时：岗位正文路径同步改（文件系统是会话间唯一共享真相，路径失效必须当轮落盘）

## 维护

- 项目大事实变更（改名/迁径/端口变/禁令新增）→ 改岗位对应行，当轮落盘
- HANDOFF 日常更新**不需要**改岗位正文（岗位只指向不复制）
- 岗位失活（项目判死）→ 删 md 并在登记处销账，不留僵尸岗
