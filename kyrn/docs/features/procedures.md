# 做法变技能（`procedures`，skill.capture）

日期：2026-10-19。代码在 `packages/kyrn-judge/src/decisions/skill-capture.ts`（问题）、`src/memory/skill-drafts.ts`（草稿的解析、存放、安装）和 `src/extension/features/procedures.ts`（什么时候问、`/skills` 命令）。测量脚本是 `kyrn/spikes/judge-bench/skill-capture-bench.ts`，用例在同目录的 `skill-capture-cases.ts`。

## 问题

经验库（`experience-library.md`）记的是一行一条的经验：某种情况下该怎么做。一套做法记不进一行：发一个版本要先改版本号、再写变更记录、构建、测试、打 tag、推送、发布、最后确认，顺序和每一步的命令都要对。代理第二次做同类的事，只能从头再摸一遍。Hermes 和 Gemini CLI 都有"代理自己写技能"的做法（Hermes 直接写，Gemini CLI 放进待审区）。

## 做法

- **只在值得的时候问。** 一回合最多问一次，而且只问这样的运行：至少 `minSteps`（6）步，至少跑过 `minCommands`（2）条 shell 命令，最后一步没出错，也不是被打断或出错结束的。普通回合一次判定都不加。子代理不问：它的运行是父代理运行的一部分。
- **判定器只判断。** 问题是选择题：这次的工作是 `procedure`（同样的步骤能做下一件同类的事，这个项目或别的项目）、`one_off`（只为这一件事）、`covered`（已装的技能覆盖了），还是 `unclear`。状态里给运行摘要（和经验库同一个 `turnDigest`）和已装技能、待审草稿的名字与说明，所以照着已有技能做的运行不会再起草一次。`procedure` 的概率到 0.7 才起草。
- **写作模型起草。** 用经验库同一个写作模型（没配就用当前对话的模型，关掉思考），按 SKILL.md 格式写：front matter 的 `name` 和 `description`，然后"什么时候用"、编号的步骤（用这次运行里的原命令，下次会变的地方用 `<占位符>`）、怎么确认做成了。只留奏效的步骤，不写密钥。解析不出 front matter、名字或说明为空的回复丢掉；名字转成文件夹能用的形式；环境里的密钥和形似凭证的字符串换成 `[redacted]`。
- **等用户决定。** 草稿放在 `<agent 目录>/mu/skill-drafts/<名字>/`（`SKILL.md` + 来源 `draft.json`），这里不是 pi 找技能的地方，草稿不会被加载。会话里提示一次：`/skills` 列出草稿，`/skills show <名字>` 看全文，`/skills accept <名字>` 装进 `<agent 目录>/skills/`（加 `--project` 装进项目的 `.pi/skills/`），`/skills reject <名字>` 丢掉。同名技能已存在时拒绝安装，不覆盖用户自己的技能。装好后下次会话起生效，或 `/reload`。
- **不刷屏。** 一个项目待审的草稿到 `maxPending`（3）条就不再起草，等用户先看。

## 测量

Jev 1.13（OpenCode Zen 免费版），每个运行一个请求，平均约 0.2 秒。

调参用例（`CASES`）：6 个做法（发版、合并上游、加判定点、加语言、数据库迁移、换 CI 密钥），6 个一次性工作（修空指针、解释代码、改名、修不稳定的测试、改样式、查登录问题），1 个已有技能覆盖的发版。问题措辞和 0.7 是先定的，跑了一次：

| 阈值 | 起草的做法 | 起草的其他 |
| --- | --- | --- |
| 0.7（采用） | 5 / 6 | 0 / 7 |
| 0.5 | 6 / 6 | 1 / 7 |
| 0.8 | 3 / 6 | 0 / 7 |

0.5 会把"改一个变量名"（0.58）也起草；漏掉的是"加一个判定点"（0.59）。错起草一次要花一次写作模型调用和用户的注意力，漏起草的代价是下次再摸一遍，所以取 0.7。另外改名、改样式、解释代码这类运行步数少、命令少，规则先挡掉了，到不了判定。

留出用例（`HELDOUT`）：0.7 定下之后才写，3 个做法（发 Docker 镜像、加 API 接口、清 npm audit）、3 个一次性、1 个已有技能覆盖的合并上游，只跑一次：

| 阈值 | 起草的做法 | 起草的其他 |
| --- | --- | --- |
| 0.7 | 3 / 3 | 0 / 4 |

边界：用例是作者写的运行摘要，不是真实会话；只测了判定，没测写作模型写出的技能好不好用。重跑：`node kyrn/spikes/judge-bench/skill-capture-bench.ts`，`SET=heldout` 跑留出组。
