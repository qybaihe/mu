## 会話 {#conversation}

- **一覧は 1 つ。** 会話の一覧は mu 自身のセッションファイルです。ターミナルで始めたセッションはアプリに表示され、アプリで始めたセッションは `mu -c` や `mu -r` で続けられます。
- **既定では静か。** mu が自分からモデルに伝えること（検証のリマインダー、目標の続行、新しいエラー、巻き戻しなど）は、あなたの言語で 1 行にまとめて表示され、原文はワンクリックで見られます。一連のツール呼び出しは、*ファイルを 3 件読み込み · コマンドを 1 件実行* のように、何をしたかを示す 1 行に折りたたまれます。
- **ファイルは横に開きます。** ツール呼び出しが読み書きしたファイルのパスや、返信に出てくるファイルをクリックすると、作業パネルのプレビューで開きます。コードなどのテキスト、Markdown、HTML、PDF、CSV、画像、diff に対応しています。それ以外のファイルは、それぞれのアプリで開きます。
- **開発サーバーはアプリの中で開きます。** コマンドが `http://localhost:5173/` のようなローカルアドレスを出力すると、その下にボタンが出て、作業パネルのブラウザでそのページを開けます。
- **どのメッセージからでもフォーク。** 各メッセージにフォークボタンがあり、その時点から新しいブランチを始められます。
- **メッセージの前に戻る。** ファイルを変更したターンのあなたのメッセージには、その下に、mu がそのとき取ったチェックポイントへ戻るボタンがあります。mu は、ファイルと会話のどちらを戻すか、両方戻すかを尋ねます。会話を戻すと、そのメッセージが入力欄に戻り、もう一度送れます。
- **行のメニュー。** 会話の名前の変更、ピン留め、未読にする、アーカイブ、削除ができます。

## 会話があなたを待っているとき {#attention}

- **通知。** ほかの会話が終わったり、あなたを待っていたりすると、システムが知らせます。
- **Dock アイコンの数字**で、あなたを待っている会話の数がわかります（macOS。Linux ではランチャーのアイコン）。
- **音で知らせることもできます。** 設定 → システム →「会話が終わったときや対応が必要なときに音を鳴らす」。mu が前面にあっても鳴り、mu が質問するときや実行が失敗したときは別の音が鳴ります。オンの間はシステム通知が無音になるので、音が二重に鳴ることはありません。既定ではオフです。
- **会話の実行中はコンピュータがスリープしません。** アイドル時のスリープで長い実行が途切れることはありません。ディスプレイは消えますし、蓋を閉じればスリープします。設定 → システムでオフにできます。

## 入力欄 {#send-box}

- **権限モード。** フルアクセス、判定モード、最小権限を、会話ごとに切り替えます。[権限と安全性](@docs/permissions)を参照してください。
- **目標。** 目標を設定すると、それが満たされるまでエージェントは作業を続けます。目標の実行中は、入力欄の上の目標の行に状態が表示されます。[目標モード](@docs/goal)を参照してください。
- **コンテキストリング。** コンテキストがどれだけ埋まっているかが、ひと目でわかります。
- **キューに入るメッセージ。** エージェントの作業中に送ったメッセージはキューで待ち、使われる前なら取り消せます。
- **スラッシュコマンド。** `/` を入力すると、mu と pi のコマンドが出ます。ターミナルと同じです。
- **あなたが指し示したものは、次のメッセージと一緒に送られます。** ページの要素、スクリーンショット、ページのコンソール、diff の行へのコメントは、送るまで入力欄にチップとして並び、送る前に外すこともできます。
- **バックグラウンドのコマンド。** 開発サーバー、ウォッチャー、時間のかかるビルドのようなコマンドがバックグラウンドで動いている間は、入力欄の横のピルにその数が表示されます。一覧には、各コマンド、実行時間、ログが並び、1 つずつ、またはまとめて止められます。会話のフォルダにスクリプト入りの package.json があると、ピルに**実行**が出てスクリプトが並びます。「実行」でバックグラウンドジョブとして起動し、終わると mu に伝わるので、テストがなぜ失敗したかをそのまま mu に聞けます。ターミナルでは `/jobs start [--name <label>] <command>` で同じことができます。

## キーボード {#keys}

Windows と Linux では <kbd>⌘</kbd> を <kbd>Ctrl</kbd> に読み替えてください。

| キー | 動作 |
| --- | --- |
| <kbd>⌘K</kbd> | コマンドパレット：会話、設定、コマンド |
| <kbd>⌘P</kbd> | 会話のフォルダ内のファイルを名前で開く |
| <kbd>⌘1</kbd>〜<kbd>⌘9</kbd> | サイドバーのその位置にある会話を開く |
| <kbd>⇧⌘A</kbd> | 離れている間に終わった、または質問してきた次の会話を開く |
| <kbd>Ctrl Tab</kbd>、<kbd>Ctrl ⇧ Tab</kbd> | 下または上の会話を開く |
| <kbd>⌘/</kbd> | アプリのすべてのショートカットを一覧表示 |

この一覧はコマンドパレットや「ヘルプ → キーボードショートカット」からも開けます。キーはお使いのシステムの表記で表示されます。

## 作業パネル {#panel}

会話の横のパネルには 8 つのタブがあります：

| タブ | 表示する内容 |
| --- | --- |
| **ボード** | [わかりやすいボード](@docs/board)：作業がどこまで進んだか、いま何が起きているか、何があなたを待っているか、そして経過の記録 |
| **判定** | リアルタイムの台帳：すべての判定と、その問い、答え、確率、所要時間 |
| **ハイブ** | [ハイブ](@docs/hive)：各ビーと、それぞれが何をしているか、どの発見が誰に届いたかのマップ |
| **教訓** | [教訓ライブラリ](@docs/lessons)：mu が学んだこと、各教訓が呼び出された回数と守られた回数。教訓の編集や廃止もできます |
| **ファイル** | プロジェクトのファイル |
| **プレビュー** | 作業中のファイルやページ：コード、Markdown、HTML、PDF、CSV、画像、diff |
| **ソース** | フォルダの git の変更とその diff、コミット欄、ブランチのプルリクエスト |
| **ブラウザ** | エージェントが一歩ずつ操作する内蔵ブラウザと、その目標。一時停止、操作の引き継ぎ、停止ができます |

**パネルはエージェントを追います。** パネルがファイル、プレビュー、ソース、ブラウザのいずれかで開いているときは、エージェントが書き終えたファイルがプレビューに表示され、エージェントがブラウザを使うとブラウザのタブが前面に出ます。閉じているパネルには点が付くだけです。これらのタブにあるスイッチで、追従をオフにできます。

### ソース管理 {#source}

- **ステージとコミット。** ファイル単位やセクション単位でステージ・ステージ解除し、メッセージを書いて <kbd>⌘Enter</kbd> でコミットします。何もステージしていないときは、「すべてコミット」が新しいファイルも含めてすべての変更を先にステージします。git が拒否したとき（フックの失敗や、ID の未設定など）は、その出力がコミット欄の下に表示されます。
- **変更を 1 つずつ。** ファイルの diff では変更ごとに「この変更をステージ」ボタンがあり、ステージ済みの diff では「この変更のステージを解除」になるので、ファイルの一部だけをコミットできます。ステージしてもディスク上のファイルは変わりません。
- **mu にコミットを任せる。** mu が変更をいくつかのコミットに分け、それぞれのメッセージを書きます。計画を見せ、あなたが同意したときだけコミットします。
- **ここでは何も捨てません。** このタブに破棄ボタンはありません。ファイルを元に戻すには、メッセージの前に戻ります。
- **ブランチのプルリクエスト。** ブランチの行の下に、プルリクエストの番号とタイトル（クリックで GitHub で開く）、状態、チェックがいくつ通ったかが表示されます。その数をクリックするとチェックの一覧が出て、個々のチェックを開けます。実行中のチェックがある間は、30 秒ごとに更新されます。プルリクエストのないブランチでは、「mu に作成させる」でブランチのプッシュとプルリクエストの作成を mu に頼めます。作成の前に、mu がタイトル、説明、送り先のリポジトリとベースブランチを見せます。これには GitHub の `gh` CLI を、あなたのアカウントでサインインした状態で使います。`gh` がなければ、この行は表示されません。

### diff へのコメント {#diff-comments}

プレビューの diff では、行の横のボタンでその行の下にコメント欄が開きます。コメントは次のメッセージと一緒に送られ、それぞれにファイル、行、コードが付きます。

### 内蔵ブラウザ {#browser}

内蔵ブラウザは専用のプロファイルを使い、あなた自身のブラウザには一切触れません。各ステップでは、何をクリックしたかと判定器の確信度が表示されます。送信、支払い、削除の前には止まり、まずあなたに確認します。

あなたが見ているものを mu に見せるボタンが 3 つあります：

- **要素を選ぶ。** ページの要素をクリックします。そのクリックはページには届きません。要素は、ページのアドレス、その要素を見つけるセレクター、テキスト、スタイル、HTML、それに要素の画像と一緒に次のメッセージに入ります。<kbd>↑</kbd> で親要素を選び、<kbd>Esc</kbd> で取り消します。
- **スクリーンショット。** ページの今の表示を、画像として次のメッセージに入れます。
- **コンソール。** ページが読み込み後にエラーや警告を出していると、その件数を示すボタンが出ます。押すと直近の 50 件が、古い順に、それぞれの出どころ付きで次のメッセージに入ります。

## モデルへのサインイン {#models}

設定 → モデルでは、アプリを離れずにモデルをつなげます。ChatGPT でサインインするか、pi が対応する任意のプロバイダーの API キーを貼り付けます。自分のサーバーも使え、自分のマシンやネットワーク上のただの `http://` アドレスも指定できます。

Google の 2 つのサインインは、Google が自社のツールのために用意したログインです。ほかのプログラムから使うと Google の規約に反する可能性があるため、アプリは先にそのリスクを示し、あなたが同意した場合にだけ進みます。Gemini API キーと Vertex AI では、こうした手順は要りません。

## 設定 {#settings}

設定は領域ごとにグループ化されています：**環境設定**、**モデル**、**カーネル**、**詳細**、**能力**、**システム**。サイドバー上部の検索ボックスで、どの設定でも探せます。

- **カーネル**では、機能ごとに 1 行でスイッチがあり、その下にその機能の判定ポイントが、それぞれのスイッチ付きで並びます。「判定器」ページでは、誰が答えるかを選びます。
- **能力**では、スキルが出どころ別（mu のもの、プロジェクトのもの、Claude Code・Codex・Cursor から引き継いだもの）に並び、スキルのフォルダを追加したり、自分で追加したものを削除したりできます。MCP サーバーも一覧され、それぞれにスイッチがあります。引数としてサーバーに渡すキーはマスクされます。
- **システム**には、通知音と、実行中にスリープしないためのスイッチがあります。
- 設定で変更した内容はすべて `~/.mu/agent/mu.json` に書き込まれるので、コマンドラインにも反映されます。逆も同じです。

表示言語は 13 言語で、簡体字中国語、繁体字中国語、英語、日本語、韓国語などがあります。

## 会話のインポート {#import}

Claude Code、Codex CLI、ZCode の会話を、メッセージ、ツール呼び出し、思考、画像を含む履歴ごとインポートして、mu で続けられます。初回ガイドは会話が見つかると最初の画面でインポートを提案し、設定からも行えます。同じ会話をもう一度インポートすると、その後の新しい内容が加わります。コマンドラインでは `mu import --list` と `mu import <file>` で行います。

## 更新、プロキシ、ログ {#updates}

- **更新。** 新しいリリースが出ると、アプリはそのサイズとともに知らせます。あなたが同意してからダウンロードし、次の再起動時にインストールします。
- **プロキシ。** `HTTPS_PROXY` が設定されていなければ、アプリ内の mu、サインイン、キーの確認はシステムのプロキシに従います。
- **ログ。** 設定 → 情報からログフォルダを開けます。
