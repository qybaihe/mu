デスクトップアプリは、mu とそのランタイムを内蔵した macOS、Windows、Linux 向けのネイティブアプリです。コマンドラインと同じエージェントと判定カーネルを専用のプロセスで動かすので、コマンドラインでできることはすべてアプリでもできます。さらに会話の横に作業パネルがあり、エージェントと判定器が何をしているかを見られます。

## 会話 {#conversation}

- **一覧は 1 つ。** 会話の一覧は mu 自身のセッションファイルです。ターミナルで始めたセッションはアプリに表示され、アプリで始めたセッションは `mu -c` や `mu -r` で続けられます。
- **既定では静か。** mu が自分からモデルに伝えること（検証のリマインダー、目標の続行、新しいエラー、巻き戻しなど）は、あなたの言語で 1 行にまとめて表示され、原文はワンクリックで見られます。一連のツール呼び出しは、*ファイルを 3 件読み込み · コマンドを 1 件実行* のように、何をしたかを示す 1 行に折りたたまれます。
- **どのメッセージからでもフォーク。** 各メッセージにフォークボタンがあり、その時点から新しいブランチを始められます。
- **行のメニュー。** 会話の名前の変更、ピン留め、未読にする、アーカイブ、削除ができます。
- **通知。** ほかの会話が終わったり、あなたを待っていたりすると、システムが知らせます。

## 入力欄 {#send-box}

- **権限モード。** フルアクセス、判定モード、最小権限を、会話ごとに切り替えます。[権限と安全性](@docs/permissions)を参照してください。
- **目標。** 目標を設定すると、それが満たされるまでエージェントは作業を続けます。目標の実行中は、入力欄の上の目標の行に状態が表示されます。[目標モード](@docs/goal)を参照してください。
- **コンテキストリング。** コンテキストがどれだけ埋まっているかが、ひと目でわかります。
- **キューに入るメッセージ。** エージェントの作業中に送ったメッセージはキューで待ち、使われる前なら取り消せます。
- **スラッシュコマンド。** `/` を入力すると、mu と pi のコマンドが出ます。ターミナルと同じです。

<kbd>⌘K</kbd>（Windows と Linux では <kbd>Ctrl K</kbd>）でコマンドパレットが開きます。

## 作業パネル {#panel}

会話の横のパネルには 8 つのタブがあります：

| タブ | 表示する内容 |
| --- | --- |
| **ボード** | [わかりやすいボード](@docs/board)：作業がどこまで進んだか、いま何が起きているか、何があなたを待っているか、そして経過の記録 |
| **判定** | リアルタイムの台帳：すべての判定と、その問い、答え、確率、所要時間 |
| **ハイブ** | [ハイブ](@docs/hive)：各ビーと、それぞれが何をしているか、どの発見が誰に届いたかのマップ |
| **教訓** | [教訓ライブラリ](@docs/lessons)：mu が学んだこと、各教訓が呼び出された回数と守られた回数。教訓の編集や廃止もできます |
| **ファイル** | プロジェクトのファイル |
| **プレビュー** | 作業中のページやファイルのプレビュー |
| **ソース** | フォルダの git の変更とその diff |
| **ブラウザ** | エージェントが一歩ずつ操作する内蔵ブラウザと、その目標。一時停止、操作の引き継ぎ、停止ができます |

内蔵ブラウザは専用のプロファイルを使い、あなた自身のブラウザには一切触れません。各ステップでは、何をクリックしたかと判定器の確信度が表示されます。送信、支払い、削除の前には止まり、まずあなたに確認します。

## モデルへのサインイン {#models}

設定 → モデルでは、アプリを離れずにサインインできます。ChatGPT、Claude、Grok、Google（Gemini CLI または Antigravity）のサブスクリプションか、pi が対応する任意のプロバイダーの API キーを使えます。自分のサーバーも使え、自分のマシンやネットワーク上のただの `http://` アドレスも指定できます。各モデルの思考レベルもここで変更できます。

Google の 2 つのサインインは、Google が自社のツールのために用意したログインです。ほかのプログラムから使うと Google の規約に反する可能性があるため、アプリは先にそのリスクを示し、あなたが同意した場合にだけ進みます。Gemini API キーと Vertex AI では、こうした手順は要りません。

## 設定 {#settings}

設定は領域ごとにグループ化され、どのページも短くなっています：**環境設定**、**モデル**、**カーネル**、**詳細**、**能力**、**システム**。サイドバー上部の検索ボックスで、どの設定でも探せます。

- **カーネル**では、機能ごとに 1 行でスイッチがあり、その下にその機能の判定ポイントが、それぞれのスイッチ付きで並びます。「判定器」ページでは、誰が答えるかを選びます。
- **能力**では、スキルが出どころ別（mu のもの、プロジェクトのもの、Claude Code・Codex・Cursor から引き継いだもの）に並び、スキルのフォルダを追加したり、自分で追加したものを削除したりできます。MCP サーバーも一覧され、それぞれにスイッチがあります。引数としてサーバーに渡すキーはマスクされます。
- 設定で変更した内容はすべて `~/.mu/agent/mu.json` に書き込まれるので、コマンドラインにも反映されます。逆も同じです。

ライトとダークはシステムに従います。表示言語は 13 言語で、簡体字中国語、繁体字中国語、英語、日本語、韓国語などがあります。

## 会話のインポート {#import}

Claude Code と Codex CLI の会話をインポートして、mu で続けられます。初回ガイドは会話が見つかるとインポートを提案し、コマンドラインでは `mu import --list` と `mu import <file>` で行います。

## 更新、プロキシ、ログ {#updates}

- **更新。** 新しいリリースが出ると、アプリはそのサイズとともに知らせます。あなたが同意してからダウンロードし、次の再起動時にインストールします。
- **プロキシ。** `HTTPS_PROXY` が設定されていなければ、アプリ内の mu、サインイン、キーの確認はシステムのプロキシに従います。
- **ログ。** 設定 → 情報からログフォルダを開けます。
