## 대화 {#conversation}

- **목록 하나를 함께 써요.** 대화 목록은 mu 자체의 세션 파일이에요. 터미널에서 시작한 세션이 앱에 보이고, 앱에서 시작한 세션은 `mu -c`나 `mu -r`로 이어 갈 수 있어요.
- **기본적으로 조용해요.** mu가 스스로 모델에게 하는 말(검증하라는 알림, 목표 이어 가기, 새 오류, 되돌리기 등)은 여러분의 언어로 된 한 줄로 보이고, 원문은 한 번 클릭하면 볼 수 있어요. 연달아 실행된 도구 호출은 무엇을 했는지 알려 주는 한 줄로 접혀요. 예: *파일 3개 읽음 · 명령 1개 실행*.
- **파일은 옆에서 열려요.** 도구 호출이 읽거나 쓴 파일의 경로, 또는 답변에 나온 파일을 클릭하면 작업 패널의 미리보기에서 열려요. 코드와 그 밖의 텍스트, Markdown, HTML, PDF, CSV, 이미지, diff를 보여 줘요. 다른 파일은 각자의 앱에서 열려요.
- **개발 서버는 앱 안에서 열려요.** 명령이 `http://localhost:5173/` 같은 로컬 주소를 출력하면, 그 아래에 버튼이 생겨서 작업 패널의 브라우저로 그 페이지를 열 수 있어요.
- **어느 메시지에서든 분기.** 메시지마다 분기 버튼이 있어서, 그 지점부터 새 브랜치를 시작해요.
- **메시지 이전으로 되돌리기.** 파일을 바꾼 턴의 내 메시지 아래에는, mu가 그때 만든 체크포인트로 돌아가는 버튼이 있어요. mu는 파일과 대화 중 무엇을 되돌릴지, 아니면 둘 다 되돌릴지 물어봐요. 대화를 되돌리면 그 메시지가 입력창으로 돌아와서 다시 보낼 수 있어요.
- **행 메뉴.** 대화의 이름 바꾸기, 고정, 읽지 않음으로 표시, 보관, 삭제.

## 대화가 여러분을 기다릴 때 {#attention}

- **알림.** 다른 대화가 끝나거나 여러분을 기다리면 시스템이 알려 줘요.
- **Dock 아이콘의 숫자**로 여러분을 기다리는 대화가 몇 개인지 알 수 있어요(macOS. Linux에서는 런처 아이콘).
- **원하면 소리로도 알려 줘요.** 설정 → 시스템 → 「대화가 끝나거나 내가 필요할 때 소리 내기」. mu가 앞에 떠 있어도 울리고, mu가 무언가를 묻거나 실행이 실패하면 다른 소리가 나요. 켜 두는 동안에는 시스템 알림이 소리를 내지 않아서 소리가 두 번 나지 않아요. 기본값은 꺼짐이에요.
- **대화가 실행되는 동안 컴퓨터가 잠들지 않아요.** 그래서 유휴 상태 잠자기 때문에 긴 실행이 끊기지 않아요. 화면은 꺼질 수 있고, 덮개를 닫으면 잠자기에 들어가요. 설정 → 시스템에서 끌 수 있어요.

## 입력창 {#send-box}

- **권한 모드.** 전체 접근, *판정 모드*, 최소 권한 중 하나를 대화마다 바꿔요. [권한과 안전](@docs/permissions)을 보세요.
- **목표.** 목표를 정하면 그 조건이 충족될 때까지 에이전트가 계속 일해요. 목표가 진행되는 동안 입력창 위의 목표 줄이 그 상태를 보여 줘요. [목표 모드](@docs/goal)를 보세요.
- **컨텍스트 링.** 컨텍스트가 얼마나 찼는지 한눈에 보여 줘요.
- **대기 중인 메시지.** 에이전트가 일하는 중에 보낸 메시지는 대기열에서 기다리고, 쓰이기 전에 다시 거둘 수 있어요.
- **슬래시 명령어.** `/`를 입력하면 터미널에서와 같은 mu와 pi의 명령어가 나와요.
- **여러분이 가리킨 것은 다음 메시지와 함께 가요.** 페이지 요소, 스크린샷, 페이지 콘솔, diff 줄에 단 댓글은 보낼 때까지 입력창에 칩으로 보이고, 보내기 전에 뺄 수 있어요.
- **백그라운드 명령.** 개발 서버, 감시 프로세스, 오래 걸리는 빌드 같은 명령이 백그라운드에서 도는 동안에는 입력창 옆 알약 모양 표시가 몇 개인지 보여 줘요. 목록에는 명령마다 실행 시간과 로그가 나오고, 하나씩 또는 전부 멈출 수 있어요. 대화 폴더에 스크립트가 든 package.json이 있으면 이 표시에 **실행**이 나오고 스크립트가 나열돼요. 「실행」을 누르면 백그라운드 작업으로 시작하고, 끝나면 mu에게 알려 주니까 테스트가 왜 실패했는지 바로 물어볼 수 있어요. 터미널에서는 `/jobs start [--name <label>] <command>`가 같은 일을 해요.

## 키보드 {#keys}

Windows와 Linux에서는 <kbd>⌘</kbd> 대신 <kbd>Ctrl</kbd>을 눌러요.

| 키 | 하는 일 |
| --- | --- |
| <kbd>⌘K</kbd> | 명령어 팔레트: 대화, 설정, 명령어 |
| <kbd>⌘P</kbd> | 대화 폴더의 파일을 이름으로 열기 |
| <kbd>⌘1</kbd>~<kbd>⌘9</kbd> | 사이드바에서 그 위치에 있는 대화 열기 |
| <kbd>⇧⌘A</kbd> | 자리를 비운 사이 끝났거나 질문한 다음 대화 열기 |
| <kbd>Ctrl Tab</kbd>, <kbd>Ctrl ⇧ Tab</kbd> | 아래 또는 위의 대화 열기 |
| <kbd>⌘/</kbd> | 앱의 모든 단축키 보기 |

이 목록은 명령어 팔레트와 「도움말 → 키보드 단축키」에서도 열 수 있고, 키는 여러분 시스템의 표기대로 보여요.

## 작업 패널 {#panel}

대화 옆 패널에는 탭이 8개 있어요.

| 탭 | 보여 주는 것 |
| --- | --- |
| **보드** | [쉬운 말 보드](@docs/board): 일이 어디까지 왔는지, 지금 무슨 일이 있는지, 무엇이 여러분을 기다리는지, 그리고 이어지는 진행 기록 |
| **판정** | 실시간 판정 장부: 모든 판정과 그 질문, 답, 확률, 걸린 시간 |
| **하이브** | [하이브](@docs/hive): 비 하나하나, 각자 하는 일, 어떤 발견이 누구에게 갔는지 보여 주는 지도 |
| **교훈** | [교훈 라이브러리](@docs/lessons): mu가 배운 것, 교훈마다 몇 번 불려 나오고 지켜졌는지. 교훈을 편집하거나 사용 중지할 수 있어요 |
| **파일** | 프로젝트의 파일 |
| **미리보기** | 작업 중인 파일이나 페이지: 코드, Markdown, HTML, PDF, CSV, 이미지, diff |
| **소스** | 폴더의 git 변경 사항과 그 diff, 커밋 입력란, 브랜치의 풀 리퀘스트 |
| **브라우저** | 에이전트가 한 단계씩 조작하는 내장 브라우저와 그 목표. 일시 정지하거나, 직접 조작하거나, 중지할 수 있어요 |

**패널은 에이전트를 따라가요.** 패널이 파일, 미리보기, 소스, 브라우저 중 하나에 열려 있으면, 에이전트가 다 쓴 파일이 미리보기에 나오고, 에이전트가 브라우저를 쓰면 브라우저 탭이 앞으로 와요. 닫힌 패널에는 점만 찍혀요. 이 탭들에 있는 스위치로 따라가기를 끌 수 있어요.

### 소스 관리 {#source}

- **스테이징과 커밋.** 파일이나 섹션 전체를 스테이징하거나 해제하고, 메시지를 쓴 뒤 <kbd>⌘Enter</kbd>로 커밋해요. 아무것도 스테이징하지 않았다면 「모두 커밋」이 새 파일까지 포함해 모든 변경을 먼저 스테이징해요. git이 거부하면(훅이 실패했거나 사용자 정보가 설정되지 않은 경우 등) 그 출력이 커밋 입력란 아래에 나와요.
- **변경 하나씩.** 파일의 diff에서는 변경마다 「이 변경 스테이징」 버튼이 있고, 스테이징된 diff에서는 「이 변경 스테이징 해제」가 있어서 파일의 일부만 커밋할 수 있어요. 스테이징해도 디스크의 파일은 바뀌지 않아요.
- **mu에게 커밋 맡기기.** mu가 변경을 여러 커밋으로 나누고 메시지를 써요. 계획을 먼저 보여 주고, 여러분이 동의해야만 커밋해요.
- **여기서는 아무것도 버리지 않아요.** 이 탭에는 버리기 버튼이 없어요. 파일을 되돌리려면 메시지 이전으로 되돌리세요.
- **브랜치의 풀 리퀘스트.** 브랜치 줄 아래에 풀 리퀘스트의 번호와 제목(클릭하면 GitHub에서 열려요), 상태, 통과한 검사 수가 나와요. 그 숫자를 클릭하면 검사 목록이 나오고, 검사를 하나씩 열 수 있어요. 실행 중인 검사가 있으면 30초마다 새로 고쳐요. 풀 리퀘스트가 없는 브랜치에서는 「mu에게 만들게 하기」로 브랜치 푸시와 풀 리퀘스트 생성을 mu에게 맡길 수 있어요. 만들기 전에 mu가 제목, 설명, 대상 저장소와 기준 브랜치를 먼저 보여 줘요. 여기에는 여러분 계정으로 로그인한 GitHub의 `gh` CLI를 써요. `gh`가 없으면 이 줄은 나오지 않아요.

### diff에 댓글 달기 {#diff-comments}

미리보기의 diff에서 줄 옆 버튼을 누르면 그 줄 아래에 댓글 입력란이 열려요. 댓글은 다음 메시지와 함께 가고, 각각 파일, 줄, 코드가 함께 붙어요.

### 내장 브라우저 {#browser}

내장 브라우저는 자체 프로필을 쓰고, 여러분의 브라우저에는 절대 손대지 않아요. 단계마다 무엇을 클릭했는지, 판정기가 얼마나 확신했는지 보여 줘요. 제출, 결제, 삭제 전에는 멈추고 먼저 물어요.

여러분이 보고 있는 것을 mu에게 보여 주는 버튼이 세 개 있어요.

- **요소 선택.** 페이지의 요소를 클릭해요. 그 클릭은 페이지에 전달되지 않아요. 요소는 페이지 주소, 그 요소를 찾는 셀렉터, 텍스트, 스타일, HTML, 그리고 요소의 이미지와 함께 다음 메시지에 들어가요. <kbd>↑</kbd>로 부모 요소를 고르고, <kbd>Esc</kbd>로 취소해요.
- **스크린샷.** 페이지의 지금 모습을 이미지로 다음 메시지에 넣어요.
- **콘솔.** 페이지가 열린 뒤 오류나 경고를 남겼다면, 그 개수를 보여 주는 버튼이 나와요. 누르면 최근 50개를 오래된 순서대로, 각각의 출처와 함께 다음 메시지에 넣어요.

## 모델 로그인 {#models}

설정 → 모델에서 앱을 떠나지 않고 모델을 연결해요. ChatGPT로 로그인하거나, pi가 지원하는 어떤 프로바이더의 API 키든 붙여 넣을 수 있어요. 직접 운영하는 서버도 되고, 여러분의 컴퓨터나 네트워크에 있는 평범한 `http://` 주소도 돼요.

Google의 두 로그인은 Google이 자사 도구용으로 만든 로그인이에요. 다른 프로그램에서 쓰면 Google의 약관을 어길 수 있어서, 앱이 먼저 그 위험을 알리고 여러분이 동의할 때만 진행해요. Gemini API 키와 Vertex AI는 이런 절차가 필요 없어요.

## 설정 {#settings}

설정은 영역별로 묶여 있어요: **환경설정**, **모델**, **커널**, **세부 항목**, **능력**, **시스템**. 사이드바 맨 위의 검색창으로 어떤 설정이든 찾을 수 있어요.

- **커널**에는 기능 하나가 스위치와 함께 한 줄로 나와요. 그 아래에 해당 판정 지점들이 각자 스위치와 함께 있어요. 판정기 페이지에서는 누가 답할지 골라요.
- **능력**에는 스킬이 출처별로 나와요(mu의 것, 프로젝트의 것, 또는 Claude Code, Codex, Cursor에서 물려받은 것). 스킬 폴더를 추가하거나 직접 추가한 것을 지울 수 있어요. MCP 서버도 여기 나오고, 서버마다 스위치가 있어요. 서버에 인수로 넘기는 키는 가려져요.
- **시스템**에는 알림 소리와, 실행 중에 잠들지 않게 하는 스위치가 있어요.
- 설정에서 바꾼 것은 모두 `~/.mu/agent/mu.json`에 써지기 때문에 명령줄에도 그대로 적용되고, 반대도 마찬가지예요.

인터페이스는 간체 중국어, 번체 중국어, 영어, 일본어, 한국어를 포함해 13개 언어로 나와요.

## 대화 가져오기 {#import}

Claude Code, Codex CLI, ZCode의 대화는 메시지, 도구 호출, 생각, 이미지까지 기록 전체를 가져와서 mu에서 이어 갈 수 있어요. 설정 가이드는 그런 대화를 찾으면 첫 화면에서 가져오기를 제안하고, 설정에서도 할 수 있어요. 같은 대화를 다시 가져오면 그 뒤에 새로 생긴 내용이 더해져요. 명령줄에서는 `mu import --list`와 `mu import <file>`로 해요.

## 업데이트, 프록시, 로그 {#updates}

- **업데이트.** 새 릴리스가 나오면 앱이 그 크기와 함께 알려 줘요. 여러분이 동의한 뒤에만 내려받고, 다음에 다시 시작할 때 설치해요.
- **프록시.** `HTTPS_PROXY`가 설정되어 있지 않으면, 앱 안의 mu, 로그인, 키 확인이 시스템 프록시를 따라요.
- **로그.** 설정 → 정보에서 로그 폴더를 열어요.
